Vega-Lite tutorial

Turn a table into a chart by describing the data, graphical marks, and encodings in a JSON specification.

1. Identify your fields

The platform's dataset, /sales-data.json, contains month (a date), category (a product group), and sales (a number). Temporal fields represent dates, quantitative fields represent numbers, and nominal fields distinguish categories.

2. Create a simple view

This example plots individual monthly sales observations. It demonstrates syntax rather than a complete solution to a study task.

{
  "data": {"url": "/sales-data.json"},
  "mark": "point",
  "encoding": {
    "x": {"field": "month", "type": "temporal"},
    "y": {"field": "sales", "type": "quantitative"}
  }
}

Use double quotes around keys and text, commas between properties, and matching braces. JSON does not allow comments or trailing commas.

3. Choose marks and encodings

Run the example, read Console, and open Visualization. Encodings map fields to visual properties such as x-position, y-position, and color. Change the mark to match your task: bars compare quantities, lines show trends, and points show individual observations.

Add a title and descriptive axis titles where requested. A color encoding can distinguish categories; a tooltip encoding can reveal values under the pointer. Consult Documentation for the properties and syntax.

4. Distinguish observations from totals

A category can occur in several monthly rows. A task asking for total sales by category requires summing those rows, for example using "aggregate": "sum" on the sales encoding. A task asking for individual observations should retain those observations. Follow the current task's requirements for aggregation and transformations; restrictions differ between study tasks and the legacy sales task.

5. Check and refine

  1. Use Run and read Console for JSON or evaluation errors.
  2. Inspect Visualization: verify fields, mark type, axes, title, and any requested interactions.
  3. Review Test Results and revise each failing requirement.
  4. Run again, then Submit when the current task passes.

The study tasks use single-view charts and the supplied data. Build the chart described by your current task rather than copying the demonstration unchanged.
