Idyll documentation

Idyll combines written explanations with interactive controls and values that update when the reader changes an input. Use this reference throughout the Idyll tasks.

Text and component syntax

Write ordinary paragraphs directly. Use # Heading for a heading, **bold** for emphasis, and blank lines to separate paragraphs.

Components use square brackets. A property has the form name:value. A component without body text ends with /]; a component containing text needs a matching closing tag.

# An interactive article

Move the slider to explore the value.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]

Put text literals in quotes. Use numbers without quotes. Use an unquoted variable name to bind a component to that variable. Enclose evaluated expressions in backticks.

Variables and derived values

var defines a named value. Bind an input to that name so interaction can change it. Use derived for a calculation that must update whenever its inputs change.

[var name:"length" value:3 /]
[derived name:"doubleLength" value:`length * 2` /]
[Range value:length min:0 max:12 step:1 /]
Length: [Display value:length /]
Twice the length: [Display value:doubleLength /]

Declare input variables first. Define each derived value after the variables or derived values it depends on; do not initialize a var from a derived value. The preview evaluates declarations in dependency order as written.

A derived value is a formula, rather than a fixed initial number. Use the same variable name consistently in the control, formula, and displayed output.

Arithmetic and comparisons

Arithmetic supports +, -, *, /, %, and parentheses. Write multiplication explicitly, such as length * 2. Parentheses control which part is evaluated first.

Comparisons include <, <=, >, >=, ===, and !==. Combine comparisons with && (and) or || (or).

Sliders and numeric input

Range

Range creates a slider. Bind value to a variable, set min and max to the required bounds, and use step:1 for integer steps.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]
Level: [Display value:level /]

TextInput

TextInput provides an editable field. For numeric entry use type:"number", the required bounds, and step:1. Its value can arrive as text; multiplication or division coerces numeric text when calculating a numeric result.

[var name:"distance" value:4 /]
[TextInput value:distance type:"number" min:0 max:20 step:1 /]
[derived name:"scaledDistance" value:`distance * 2` /]
Scaled distance: [Display value:scaledDistance /]

Use a slider when the task explicitly asks for one. The task requirements determine the appropriate control and bounds.

Displaying values

Display inserts a value into the article and updates it when the value changes. Add surrounding text to identify the quantity and its units. A fixed number typed into a paragraph will not update.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]
Current level: [Display value:level /]
Doubled level: [Display value:`level * 2` /]

Conditional text

Conditional shows its body only when its if expression is true. Close each block with [/Conditional]. Use separate conditions for separate messages.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]
Level: [Display value:level /]
[Conditional if:`level < 6`]Below the midpoint[/Conditional]
[Conditional if:`level >= 6`]At or above the midpoint[/Conditional]

For several intervals, choose inclusive and exclusive endpoints carefully so messages neither overlap nor leave gaps. Test the values immediately below, at, and above each boundary.

Data and linked views

Levels 2 and 3 provide a fixed local sales dataset with month, category, and sales fields. Copy the supplied article from Task Description; you only need to add interaction code. Load the data using exactly this declaration:

[data name:"sales" source:"sales-data.json" /]

Use array expressions to derive new views of the data. filter keeps matching rows, map creates a value for each row, and reduce combines rows. Arrow callbacks use a local parameter such as row => row.sales >= minimum. These expressions update when referenced controls change.

[data name:"sales" source:"sales-data.json" /]
[var name:"minimum" value:100 /]
[derived name:"matches" value:`sales.filter(row => row.sales >= minimum)` /]
[Range value:minimum min:0 max:500 step:10 /]
[Table data:matches /]
[Chart data:matches type:"point" x:"month" y:"sales" color:"category" /]

This demonstrates a single filter, rather than a complete study solution. Table displays the supplied rows; Chart renders the supplied data. Neither component automatically applies task filters or calculates summaries.

Choosing categories

[var name:"category" value:"All" /]
[Select value:category options:`["All", "Books", "Games", "Music"]` /]

Bind Select to a mutable variable just like Range. Combine conditions with && and ||. A filter compares each row's category and sales with the current control values.

Totals, means, and empty results

matches.length gives the row count. matches.reduce((sum, row) => sum + row.sales, 0) gives the total. Guard division when calculating an average: count ? total / count : '—'. A conditional message can explain why no rows are shown.

For the explorer's summaries, identify Display components with role:"count", role:"total", and role:"average". Use format:".0f" for integer counts or format:".2f" for a mean. Pass an empty array to Table and Chart when nothing matches.

Chart properties

  • data: the rows to render; type: "point" or "line".
  • x:"month" y:"sales" color:"category": the fields used by the chart.
  • focus: a category to emphasize while fading other categories; use an empty string for no emphasis.
  • reference: a separate array of objects with month and sales values, rendered as a reference line.
  • highlight: an array of data rows to mark as highlighted observations.

Calculate reference and highlighted rows yourself using derived expressions. Use empty arrays when those layers are not needed. For a monthly reference, group by the month field and calculate the mean over the full dataset for that month, rather than over only the selected category.

Scroll-driven articles

Scroller binds the active section to a mutable step variable. Step wraps a narrative section with a zero-based index. Pinned holds a shared chart and controls on the right. These layout components do not select chart data or calculate averages.

[var name:"page" value:0 /]
[Scroller step:page]
[Step index:0]
## First perspective
Paste the first supplied section here.
[/Step]
[Step index:1]
## Second perspective
Paste the second supplied section here.
[/Step]
[Pinned]
Current section: [Display value:page /]
[/Pinned]
[/Scroller]

For the study story, include all four Step sections and place the category control, threshold control, stage display, and shared Chart inside one Pinned block. Put the article title and introduction before Scroller, and the closing section after it.

The active step changes when a section's top crosses 40% of the preview viewport, including while scrolling upward. Build derived expressions that map this step and the current controls to the chart's data, focus, reference, and highlight properties. Changing one control should not reset the other control or the current step.

Identify the stage display with role:"stage" and compute the stage name from the bound step. Use the exact stage names listed in Task Description.

Running and checking your article

  1. Write the article in the editor and choose Run.
  2. Read Console output for compiler or execution errors.
  3. Open Compiled Article and change the inputs. Confirm displayed calculations and messages update correctly, including at the endpoints.
  4. Open Checks to review each requirement. Revise and run again as needed.
  5. Choose Submit when the requirements pass. A successful submission unlocks the next task.

If the article does not compile, check matching brackets, quotes, backticks, and closing tags. If a value stays fixed, check its binding and use a derived expression rather than a constant.

Supported features in this platform

The task checker supports unstyled bound controls, derived values, arithmetic, comparisons, conditional expressions, selected Math helpers, and bounded array operations for the advanced tasks. Use the supplied Table, Chart, Scroller, Step, and Pinned components for linked views and scroll narratives.

Only the fixed sales dataset is available; external or asynchronous data imports and front matter are unavailable. Array callbacks must be simple expressions. Arbitrary function calls, statements, side effects, custom components, and custom styles are outside the checker’s supported subset. Keep your task logic in derived expressions.
