Idyll documentation

Idyll combines written explanations with interactive controls and values that update when the reader changes an input. Use this reference throughout the Idyll tasks.

Text and component syntax

Write ordinary paragraphs directly. Use # Heading for a heading, **bold** for emphasis, and blank lines to separate paragraphs.

Components use square brackets. A property has the form name:value. A component without body text ends with /]; a component containing text needs a matching closing tag.

# An interactive article

Move the slider to explore the value.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]

Put text literals in quotes. Use numbers without quotes. Use an unquoted variable name to bind a component to that variable. Enclose evaluated expressions in backticks.

Variables and derived values

var defines a named value. Bind an input to that name so interaction can change it. Use derived for a calculation that must update whenever its inputs change.

[var name:"length" value:3 /]
[derived name:"doubleLength" value:`length * 2` /]
[Range value:length min:0 max:12 step:1 /]
Length: [Display value:length /]
Twice the length: [Display value:doubleLength /]

A derived value is a formula, rather than a fixed initial number. Use the same variable name consistently in the control, formula, and displayed output.

Arithmetic and comparisons

Arithmetic supports +, -, *, /, %, and parentheses. Write multiplication explicitly, such as length * 2. Parentheses control which part is evaluated first.

Comparisons include <, <=, >, >=, ===, and !==. Combine comparisons with && (and) or || (or).

Sliders and numeric input

Range

Range creates a slider. Bind value to a variable, set min and max to the required bounds, and use step:1 for integer steps.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]
Level: [Display value:level /]

TextInput

TextInput provides an editable field. For numeric entry use type:"number", the required bounds, and step:1. Its value can arrive as text; multiplication or division coerces numeric text when calculating a numeric result.

[var name:"distance" value:4 /]
[TextInput value:distance type:"number" min:0 max:20 step:1 /]
[derived name:"scaledDistance" value:`distance * 2` /]
Scaled distance: [Display value:scaledDistance /]

Use a slider when the task explicitly asks for one. The task requirements determine the appropriate control and bounds.

Displaying values

Display inserts a value into the article and updates it when the value changes. Add surrounding text to identify the quantity and its units. A fixed number typed into a paragraph will not update.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]
Current level: [Display value:level /]
Doubled level: [Display value:`level * 2` /]

Conditional text

Conditional shows its body only when its if expression is true. Close each block with [/Conditional]. Use separate conditions for separate messages.

[var name:"level" value:3 /]
[Range value:level min:0 max:12 step:1 /]
Level: [Display value:level /]
[Conditional if:`level < 6`]Below the midpoint[/Conditional]
[Conditional if:`level >= 6`]At or above the midpoint[/Conditional]

For several intervals, choose inclusive and exclusive endpoints carefully so messages neither overlap nor leave gaps. Test the values immediately below, at, and above each boundary.

Running and checking your article

  1. Write the article in the editor and choose Run.
  2. Read Console output for compiler or execution errors.
  3. Open Compiled Article and change the inputs. Confirm displayed calculations and messages update correctly, including at the endpoints.
  4. Open Checks to review each requirement. Revise and run again as needed.
  5. Choose Submit when the requirements pass. A successful submission unlocks the next task.

If the article does not compile, check matching brackets, quotes, backticks, and closing tags. If a value stays fixed, check its binding and use a derived expression rather than a constant.

Supported features in this platform

The task checker supports unstyled built-in Range and TextInput controls bound to variables, derived values, arithmetic, comparisons, logical and conditional expressions, and selected Math helpers. The examples above use this supported subset.

Custom components, data imports, and front matter are unavailable. Custom functions, arbitrary JavaScript calls, and custom styles cannot be verified by task checks, even if a preview renders them. Prefer the simple controls and expressions shown here.
